# 运行态系统设计说明书

## 1. 系统概述

### 1.1 系统定位
运行态系统是报表BI（商业智能）系统的核心运行环境，负责解析设计态生成的schema文件，实现报表界面的动态渲染、数据查询与SQL生成、交互逻辑执行、安全控制等功能。运行态与设计态采用schema文件作为桥梁，实现设计与运行的完全分离。

### 1.2 核心功能
- **Schema解析**：解析设计态生成的标准化schema文件，构建运行时数据结构
- **界面渲染**：根据schema动态渲染报表界面，支持响应式布局和组件懒加载
- **数据查询**：根据schema配置执行数据查询，支持多种数据源（数据库、API、文件等）
- **SQL生成**：动态生成SQL语句，支持参数化查询和权限过滤条件注入
- **交互逻辑执行**：执行schema中配置的交互逻辑，处理用户交互事件（下钻、关联、跳转、过滤等），支持通过REST API接口发送动态事件请求消息
- **权限验证**：验证用户对报表和数据的访问权限，支持行级和列级数据权限
- **安全控制**：提供系统安全控制能力，防止SQL注入、XSS等安全风险
- **运行态国际化**：实现报表显示文字的多语言切换功能，支持中文和英文两种语言
- **动态样式替换**：提供动态替换报表背景、图片和组件样式的功能，支持实时样式切换和个性化定制

### 1.3 系统价值
- 实现设计与运行分离，提高系统的可维护性和扩展性
- 通过schema标准化，支持报表的版本管理、复用和迁移
- 提供丰富的交互能力，支持数据下钻、关联、跳转等高级分析功能
- 支持多语言切换，满足国际化需求
- 支持动态样式定制，提供个性化的报表展示体验

## 2. 系统上下文

### 2.1 系统边界
运行态系统作为BI平台的核心运行组件，向上为业务用户提供报表查看和使用能力，向下对接各类数据源系统、权限管理系统和文件存储系统。

### 2.2 外部系统接口

#### 2.2.1 数据源系统
- **接口类型**：数据库连接（JDBC）、REST API、文件系统等
- **接口描述**：
  - 支持关系型数据库（PostgreSQL）
  - 支持大数据存储（StarRocks、HDFS）
  - 支持RESTful API数据源
- **接口协议**：JDBC协议、HTTP/HTTPS协议、文件协议

#### 2.2.2 权限管理系统
- **接口类型**：权限查询接口、权限验证接口
- **接口描述**：提供用户权限查询和验证能力，支持角色权限、数据权限等
- **接口协议**：REST API

#### 2.2.3 文件存储系统
- **接口类型**：对象存储接口
- **接口描述**：存储上传的图片、导出的报表文件、模板文件等
- **接口协议**：S3协议、OSS协议等

### 2.3 系统依赖
- **前端框架**：支持现代浏览器（Chrome、Firefox、Edge等）
- **后端服务**：需要部署应用服务器和数据库服务器
- **数据源**：需要访问权限的数据源系统
- **Schema文件**：依赖设计态生成的标准化schema文件

## 3. 使用场景

### 3.1 场景一：查看报表
**参与者**：业务用户  
**前置条件**：用户具有报表查看权限  
**工作流**：
1. 用户进入运行态界面，浏览可用的报表列表
2. 用户选择要查看的报表
3. 系统加载该报表的schema文件
4. 系统解析schema，渲染报表界面
5. 系统根据schema中配置的数据源，生成SQL语句或调用数据接口
6. 系统执行数据查询，获取数据
7. 系统将数据绑定到对应的组件，渲染图表和表格
8. 用户查看报表数据

**主要功能模块**：
- Schema解析模块
- 界面渲染模块
- 数据查询模块
- SQL生成模块

### 3.2 场景二：报表交互操作
**参与者**：业务用户  
**前置条件**：用户正在查看报表，报表配置了交互功能  
**工作流**：
1. 用户在报表中点击某个图表的数据点或区域
2. 系统识别交互事件，根据schema中配置的交互规则执行相应动作
3. 如果是下钻操作：系统传递下钻参数，重新查询数据并刷新当前组件或跳转到下钻页面
4. 如果是关联操作：系统将筛选条件传递给关联组件，触发关联组件的数据刷新
5. 如果是跳转操作：系统跳转到指定的报表或页面，并传递相关参数
6. 如果是过滤操作：系统应用过滤条件，重新查询并刷新相关组件的数据，过滤条件支持单选、多选。支持选择时间范围。
7. 如果是动态事件操作：系统根据配置的REST API接口信息，映射请求参数，发送HTTP请求，处理响应数据，执行后续动作（更新组件、触发动作、显示消息等）

**主要功能模块**：
- 事件监听模块
- 交互逻辑执行模块
- 数据刷新模块

### 3.3 场景三：权限控制
**参与者**：系统、业务用户  
**前置条件**：用户尝试访问报表或数据  
**工作流**：
1. 用户请求访问某个报表
2. 系统检查用户是否有该报表的访问权限
3. 系统检查用户是否有报表关联数据源的访问权限
4. 系统检查用户的数据权限（行级、列级权限）
5. 如果权限验证通过，系统生成带权限过滤条件的SQL语句
6. 如果权限验证失败，系统拒绝访问并提示用户

**主要功能模块**：
- 权限验证模块
- 安全控制模块

### 3.4 场景四：语言切换
**参与者**：业务用户  
**前置条件**：用户正在查看报表  
**工作流**：
1. 用户进入运行态界面，系统根据用户语言偏好（或浏览器语言）自动加载对应语言的界面和报表内容
2. 用户点击语言切换按钮（如中文/English切换器）
3. 系统获取用户选择的语言代码（zh-CN或en-US）
4. 系统保存用户语言偏好到用户配置和本地存储
5. 系统重新加载对应语言的文本资源文件
6. 系统从报表schema中提取对应语言的多语言配置
7. 系统更新报表界面：
   - 更新系统界面文本（按钮、菜单、提示信息等）
   - 更新组件标题、标签、提示文字
   - 更新数据字段名称显示
   - 更新报表元信息（如报表名称、描述等）
8. 系统刷新报表显示，用户看到切换后的多语言界面

**主要功能模块**：
- 运行态国际化模块
- 语言管理模块
- 文本资源管理模块
- 界面渲染模块

### 3.5 场景五：动态样式替换
**参与者**：业务用户  
**前置条件**：用户正在查看报表，具有样式修改权限  
**工作流**：
1. 用户进入运行态界面，查看报表
2. 用户点击样式设置按钮（或右键菜单选择样式设置）
3. 系统显示样式配置面板，展示当前样式配置
4. 用户选择要修改的样式类型：
   - **替换报表背景**：
     - 用户选择背景类型（纯色/渐变/图片）
     - 用户配置背景参数（颜色值、渐变方向、图片URL等）
     - 系统实时预览背景效果
   - **替换组件背景**：
     - 用户选择要修改的组件（单选或多选）
     - 用户配置组件背景（颜色、图片、透明度等）
     - 系统实时预览组件背景效果
   - **替换图片**：
     - 用户选择图片组件
     - 用户选择图片源（URL、上传文件、图片库）
     - 系统实时预览图片效果
   - **替换组件样式**：
     - 用户选择要修改的组件
     - 用户配置样式属性（颜色、字体、边框、阴影等）
     - 系统实时预览样式效果
5. 用户确认样式修改，系统应用样式变更
6. 系统更新报表显示，用户看到新的样式效果
7. 用户可选择保存样式配置，系统保存到用户配置或报表配置
8. 用户可选择应用预设主题，系统批量应用主题样式
9. 用户可选择重置样式，系统恢复为默认样式

**主要功能模块**：
- 动态样式替换模块
- 界面渲染模块
- 样式配置管理模块

## 4. 功能需求分析

### 4.1 逻辑视图

逻辑视图描述了运行态系统的功能分解和模块组织，展示了系统的主要功能模块及其关系。

**运行态功能层次结构**：
- **运行态层**：提供报表运行能力
  - Schema解析模块
  - 界面渲染模块
  - 数据查询模块
  - SQL生成模块
  - 交互逻辑执行模块
  - 权限验证模块
  - 安全控制模块
  - 运行态国际化模块
  - 动态样式替换模块
- **基础设施层**：提供基础服务能力
  - 权限管理服务
  - 文件存储服务
  - 数据源连接服务

**模块间依赖关系**：
- 运行态模块通过Schema解析模块读取schema文件
- 界面渲染模块依赖Schema解析模块的输出
- 数据查询模块依赖SQL生成模块生成的SQL语句
- SQL生成模块依赖权限验证模块的权限规则
- 交互逻辑执行模块依赖界面渲染模块和数据查询模块
- 运行态国际化模块为界面渲染模块提供多语言支持
- 动态样式替换模块与界面渲染模块协同工作
- 所有模块依赖基础设施层提供的服务

### 4.2 部署视图

部署视图描述了运行态系统的物理部署架构，展示了系统组件在硬件和网络环境中的分布。

**部署架构**：
- **前端部署**：
  - 运行态前端：部署在Web服务器（Nginx），支持CDN加速
  - 静态资源：图片、样式文件等存储在对象存储（OSS/MinIO）
- **后端部署**：
  - 应用服务器：部署在应用服务器集群，支持负载均衡
  - API网关：统一入口，负责路由、限流等
  - 运行态服务：独立的微服务，提供运行态API
- **数据存储**：
  - 关系数据库：MySQL/PostgreSQL主从集群，读写分离
  - 缓存：Redis集群，提供高可用缓存服务
  - 对象存储：MinIO/OSS，存储schema文件、图片等
- **外部系统**：
  - 数据源系统：通过JDBC/HTTP等协议连接
  - 权限系统：通过REST API集成

**网络拓扑**：
- 用户通过浏览器访问运行态前端应用
- 前端通过HTTPS协议调用后端API
- 后端通过内网连接数据库和缓存
- 后端通过安全通道连接外部数据源

### 4.5 数据视图

数据视图描述了运行态系统的数据模型和数据结构，展示了数据的组织方式和流转过程。

**核心数据实体**：
- **报表实体**：报表基本信息、schema文件路径、版本信息
- **组件实体**：组件配置、属性、数据源绑定、交互配置
- **数据源实体**：数据源连接信息、查询配置
- **用户实体**：用户信息、权限配置、语言偏好
- **国际化实体**：文本资源、报表多语言配置
- **样式配置实体**：样式配置、主题配置

**数据流转**：
1. **运行态数据流**：
   - Schema文件 → Schema解析 → 组件树结构
   - 组件数据源配置 → SQL生成 → 数据查询 → 数据返回
   - 用户交互 → 交互逻辑执行 → 参数传递 → 数据刷新
2. **国际化数据流**：
   - 用户语言偏好 → 语言资源加载 → 报表内容本地化
   - Schema的i18n字段 → 多语言文本提取 → 界面渲染
3. **样式数据流**：
   - 用户样式配置 → 样式应用 → 界面渲染更新
   - Schema的style字段 → 默认样式加载 → 样式配置合并

**数据存储**：
- 结构化数据：存储在关系数据库中（报表信息、用户信息等）
- 非结构化数据：存储在对象存储中（schema文件、图片等）
- 缓存数据：存储在Redis中（查询结果、权限信息、样式配置等）

### 4.6 运行态功能模块

#### 4.6.1 Schema解析模块
**功能描述**：解析设计态生成的schema文件，构建运行时数据结构  
**主要功能**：
- 解析JSON Schema文件
- 验证schema格式和完整性
- 构建组件树结构
- 提取数据源配置
- 提取交互配置
- Schema版本兼容性处理

**接口定义**：
- `parseSchema(schema)`：解析schema文件
- `validateSchemaFormat(schema)`：验证schema格式
- `buildComponentTree(schema)`：构建组件树
- `extractDatasourceConfig(schema)`：提取数据源配置
- `extractInteractionConfig(schema)`：提取交互配置

#### 4.6.2 界面渲染模块
**功能描述**：根据解析后的schema动态渲染报表界面  
**主要功能**：
- 动态加载组件库
- 根据schema渲染组件树
- 应用组件样式和属性
- 响应式布局适配
- 组件懒加载和虚拟滚动
- 渲染性能优化

**接口定义**：
- `renderReport(schema)`：渲染报表
- `renderComponent(componentConfig)`：渲染单个组件
- `updateComponentData(componentId, data)`：更新组件数据
- `refreshComponent(componentId)`：刷新组件

#### 4.6.3 数据查询模块
**功能描述**：根据schema配置执行数据查询，支持多种数据源  
**主要功能**：
- 数据源连接管理
- SQL查询执行
- REST API调用
- 文件数据读取
- 查询结果缓存
- 异步数据加载
- 数据转换和格式化

**接口定义**：
- `executeQuery(datasourceConfig, queryConfig)`：执行数据查询
- `getDatasourceConnection(datasourceId)`：获取数据源连接
- `testQuery(queryConfig)`：测试查询
- `cacheQueryResult(queryKey, result)`：缓存查询结果
- `getCachedResult(queryKey)`：获取缓存结果

#### 4.6.4 SQL生成模块
**功能描述**：根据schema中的数据源配置和查询条件动态生成SQL语句  
**主要功能**：
- 基础SQL生成（SELECT、FROM、WHERE等）
- 参数化SQL生成
- 权限过滤条件注入
- 数据权限行级过滤
- 数据权限列级过滤
- SQL优化和安全校验
- 多数据源SQL适配

**接口定义**：
- `generateSQL(datasourceConfig, queryConfig)`：生成SQL语句
- `injectPermissionFilter(sql, userPermissions)`：注入权限过滤条件
- `validateSQL(sql)`：验证SQL安全性
- `optimizeSQL(sql)`：优化SQL语句
- `adaptSQLForDatasource(sql, datasourceType)`：适配不同数据源的SQL

#### 4.6.5 交互逻辑执行模块
**功能描述**：执行schema中配置的交互逻辑，处理用户交互事件  
**主要功能**：
- 事件监听和分发
- 交互规则解析和执行
- 下钻逻辑处理
- 关联逻辑处理
- 跳转逻辑处理
- 过滤逻辑处理
- 动态事件处理：通过REST API接口发送事件请求消息，处理API响应并执行后续动作
- 参数传递和状态管理
- 控制类组件事件处理（点击、值变更、输入、搜索等）
- 控制类组件与数据展示组件的联动处理

**动态事件功能**：
- **API请求执行**：根据配置的REST API接口信息发送HTTP请求
- **参数映射处理**：将组件数据、用户操作数据、上下文数据映射为API请求参数
- **认证处理**：支持Bearer Token、API Key、Basic Auth等认证方式
- **响应解析**：使用JSONPath提取响应数据，支持数据转换和过滤
- **错误处理**：支持重试机制、降级策略、错误提示等
- **响应动作执行**：根据响应结果执行后续动作（更新组件、触发动作、显示消息等）

**接口定义**：
- `handleInteractionEvent(event, interactionConfig)`：处理交互事件

## 5. 功能实现设计

### 5.1 Schema解析模块实现
**技术实现**：
- Schema加载：从文件系统或数据库加载schema文件
- Schema解析：使用JSON解析器解析schema，构建内存数据结构
- 版本兼容：支持多版本schema格式，提供转换适配器
- 错误处理：解析失败时提供详细错误信息

**解析流程**：
1. 加载schema文件 → 验证文件格式 → 解析JSON
2. 验证schema版本 → 应用版本转换器（如需要）→ 验证schema结构
3. 构建组件树 → 提取数据源配置 → 提取交互配置 → 返回解析结果

**数据结构**：
```json
{
  "reportInfo": {},
  "componentTree": {},
  "datasourceMap": {},
  "interactionMap": {}
}
```

### 5.2 界面渲染模块实现
**技术实现**：
- 组件动态加载：根据组件类型动态加载对应组件
- 虚拟DOM：使用React/Vue等框架的虚拟DOM机制，优化渲染性能
- 懒加载：大报表支持组件懒加载，按需渲染
- 响应式布局：根据屏幕尺寸自适应调整布局

**渲染流程**：
1. 接收解析后的schema → 构建组件树 → 递归渲染组件
2. 组件挂载 → 请求组件数据 → 数据到达后更新组件
3. 交互事件绑定 → 监听用户操作 → 触发交互逻辑

**性能优化**：
- 组件虚拟滚动：只渲染可见区域的组件
- 数据缓存：缓存已加载的数据，避免重复请求
- 防抖节流：限制频繁的数据刷新操作

### 5.3 数据查询模块实现
**技术实现**：
- 连接池管理：维护数据源连接池，复用连接提高性能
- 异步查询：使用Promise/async-await处理异步查询
- 查询缓存：使用Redis等缓存查询结果，设置过期时间
- 错误重试：查询失败时自动重试，支持指数退避

**查询流程**：
1. 接收查询请求 → 检查缓存 → 缓存命中则返回缓存结果
2. 缓存未命中 → 获取数据源连接 → 执行查询 → 缓存结果 → 返回数据
3. 查询失败 → 记录错误日志 → 返回错误信息

**数据转换**：
- 数据类型转换：将数据库类型转换为前端需要的类型
- 数据格式化：日期、数字等格式化处理
- 数据聚合：支持前端数据聚合计算

### 5.4 SQL生成模块实现
**技术实现**：
- SQL构建器：使用SQL构建库动态生成SQL语句
- 参数化查询：使用参数化查询防止SQL注入
- 权限注入：在WHERE子句中注入权限过滤条件
- SQL优化：分析SQL执行计划，优化查询性能

**SQL生成流程**：
1. 接收查询配置 → 解析数据源配置 → 构建基础SQL
2. 注入查询参数 → 注入权限过滤条件 → 注入数据权限条件
3. SQL安全校验 → 检查危险关键字 → 验证参数类型
4. SQL优化 → 分析执行计划 → 应用优化规则 → 返回最终SQL

**权限注入示例**：
```sql
-- 原始SQL
SELECT * FROM sales WHERE region = ?

-- 注入权限后
SELECT * FROM sales 
WHERE region = ? 
AND department IN (SELECT department FROM user_permissions WHERE user_id = ?)
AND amount <= (SELECT max_amount FROM user_permissions WHERE user_id = ?)
```

### 5.5 交互逻辑执行模块实现
**技术实现**：
- 事件总线：使用事件总线机制处理组件间通信
- 状态管理：使用状态管理库管理全局状态和组件状态
- 交互引擎：解析交互配置，执行对应的交互逻辑
- 参数传递：支持参数映射和转换
- 控制类组件处理：监听控制类组件事件，处理参数传递和组件联动
- 动态事件引擎：HTTP客户端封装，支持REST API请求、参数映射、响应处理等功能
- 请求队列：管理并发请求，防止请求过多导致性能问题

**交互执行流程**：
1. 用户触发交互事件 → 事件监听器捕获事件 → 查找交互配置
2. 解析交互规则 → 验证交互条件 → 执行交互动作
3. 下钻：传递下钻参数 → 重新查询数据 → 更新组件或跳转页面
4. 关联：传递筛选条件 → 触发目标组件刷新 → 更新关联组件数据
5. 跳转：构建跳转URL → 传递参数 → 执行页面跳转
6. 过滤：应用过滤条件 → 重新查询数据 → 刷新相关组件
7. 动态事件：映射请求参数 → 发送REST API请求 → 处理响应 → 执行后续动作

**动态事件执行流程**：
1. 用户触发交互事件 → 检测到dynamicEvent动作类型 → 获取动态事件配置
2. 参数映射：提取组件数据、用户操作数据、上下文数据 → 根据paramMapping配置映射为API请求参数
3. 构建请求：根据apiConfig配置构建HTTP请求（URL、方法、请求头、请求体等）
4. 认证处理：根据authConfig配置添加认证信息（Bearer Token、API Key、Basic Auth等）
5. 发送请求：通过HTTP客户端发送请求，支持超时控制和请求队列管理
6. 响应处理：
   - 使用JSONPath从响应中提取数据（根据responseConfig.dataPath）
   - 判断请求是否成功（根据responseConfig.successCondition）
   - 应用数据转换（根据responseConfig.transform）
   - 提取错误信息（根据responseConfig.errorPath）
7. 错误处理：
   - 请求失败时根据errorHandling配置执行重试（支持最大重试次数和重试延迟）
   - 重试失败后执行降级策略（显示错误、使用默认值、忽略等）
8. 响应动作执行：
   - 根据responseActions配置执行后续动作
   - updateComponent：更新目标组件的数据或状态
   - triggerAction：触发其他交互动作
   - showMessage：显示提示消息

**状态管理**：
- 全局状态：存储报表级状态（筛选条件、参数、控制类组件值等）
- 组件状态：存储组件级状态（选中项、展开状态、控制类组件状态等）
- 状态同步：组件状态变更时同步到全局状态
- 控制类组件状态：存储控制类组件的值和状态，供其他组件使用

### 5.6 权限验证模块实现
**技术实现**：

- 表格列头：根据字段的资源ID从资源库查询本地化的列名
- 图表图例：根据字段的资源ID从资源库查询本地化的字段名称
- 提示信息：数据提示框中的字段名称使用资源ID查询本地化文本

**性能优化**：
- 资源库查询缓存：缓存已查询的资源ID文本映射，避免重复查询
- 批量查询：一次性查询报表中所有资源ID的文本，减少数据库查询次数
- 按需加载：只加载当前语言需要的资源，切换时再加载目标语言资源
- 批量更新：语言切换时批量更新所有组件，减少渲染次数
- 预加载：预加载用户可能使用的语言资源（如中英文）

**与界面渲染模块的集成**：
- 界面渲染模块在渲染组件时读取schema中的资源ID
- 调用本地化函数，根据资源ID从资源库查询对应的语言文本
- 语言切换时触发界面渲染模块重新渲染相关组件
- 支持组件级别的本地化更新，无需重新渲染整个报表
- 资源库查询结果缓存，提高查询性能

- 样式覆盖：使用样式覆盖机制，自定义样式覆盖默认样式

- 虚拟DOM：使用虚拟DOM技术，在确认前不实际修改DOM
- 样式隔离：使用样式隔离技术，预览样式不影响实际样式
- 预览标记：为预览状态添加标记，区分预览和实际应用
- 预览撤销：用户取消时，清除预览样式，恢复原始样式

**样式回滚机制**：
- 历史栈：维护样式变更历史栈，记录每次样式变更
- 撤销操作：从历史栈中恢复上一次样式配置
- 重做操作：支持重做已撤销的样式变更
- 历史限制：限制历史栈大小，避免内存占用过大

**图片处理**：
- 图片上传：支持图片文件上传，上传到对象存储
- 图片验证：验证图片格式、大小、尺寸等
- 图片优化：自动压缩和优化图片，提高加载速度
- 图片缓存：缓存已加载的图片，避免重复加载
- 图片占位：图片加载失败时显示占位图

**性能优化**：
- 样式缓存：缓存已应用的样式配置，避免重复计算
- 批量更新：批量应用样式变更，减少DOM操作次数
- 防抖节流：样式配置输入时使用防抖，减少实时预览频率
- 懒加载：图片资源按需加载，提高初始加载速度
- 样式合并：合并相同样式属性，减少样式对象大小

**与界面渲染模块的集成**：
- 界面渲染模块在渲染组件时读取样式配置
- 样式配置变更时通知界面渲染模块重新渲染
- 支持组件级别的样式更新，无需重新渲染整个报表
- 样式配置与组件属性分离，样式变更不影响组件功能

**权限控制**：
- 样式修改权限：检查用户是否有权限修改报表样式
- 样式保存权限：检查用户是否有权限保存样式配置
- 主题应用权限：检查用户是否有权限应用主题
- 权限验证：在样式操作前进行权限验证，无权限则拒绝操作

## 6. 模块间交互设计

### 6.1 运行态模块交互
**核心交互流程**：
1. **报表加载流程**：
   - Schema解析模块 → 加载并解析schema
   - 界面渲染模块 → 根据schema渲染界面
   - 数据查询模块 → 根据数据源配置查询数据
   - SQL生成模块 → 生成SQL并注入权限
   - 界面渲染模块 → 绑定数据到组件

2. **交互执行流程**：
   - 用户操作 → 事件监听 → 交互逻辑执行模块
   - 交互逻辑执行模块 → 解析交互配置 → 执行交互动作
   - 数据查询模块 → 重新查询数据
   - 界面渲染模块 → 更新组件数据

3. **权限控制流程**：
   - 用户请求 → 权限验证模块 → 验证访问权限
   - SQL生成模块 → 注入权限条件
   - 安全控制模块 → 安全校验
   - 数据返回 → 应用数据权限过滤

4. **国际化渲染流程**：
   - 用户访问报表 → 运行态国际化模块 → 获取用户语言偏好
   - Schema解析模块 → 解析schema并提取所有资源ID（KeyID）
   - 运行态国际化模块 → 批量查询资源库，根据资源ID和语言偏好获取对应的语言文本
   - 运行态国际化模块 → 构建资源ID到文本的映射表
   - 运行态国际化模块 → 加载系统文本资源文件
   - 界面渲染模块 → 根据资源ID从映射表获取文本 → 渲染本地化内容
   - 数据查询模块 → 返回数据 → 运行态国际化模块 → 根据字段的资源ID应用字段名称本地化
   - 界面渲染模块 → 显示本地化的字段名称

5. **语言切换流程**：
   - 用户点击语言切换 → 运行态国际化模块 → 保存语言偏好
   - 运行态国际化模块 → 重新加载目标语言的系统文本资源
   - Schema解析模块 → 从schema提取所有资源ID
   - 运行态国际化模块 → 批量查询资源库，获取目标语言对应的文本
   - 运行态国际化模块 → 更新资源ID到文本的映射表
   - 运行态国际化模块 → 通知界面渲染模块语言已切换
   - 界面渲染模块 → 根据资源ID从映射表获取新的文本 → 更新所有组件显示
   - 数据查询模块 → 如有字段映射配置，根据字段的资源ID应用新的本地化字段名称

6. **样式替换流程**：
   - 用户选择样式修改 → 动态样式替换模块 → 检查样式修改权限
   - 动态样式替换模块 → 加载当前样式配置（从schema或用户配置）
   - 用户配置样式参数 → 动态样式替换模块 → 实时预览样式效果
   - 用户确认样式修改 → 动态样式替换模块 → 应用样式变更
   - 动态样式替换模块 → 更新样式配置 → 通知界面渲染模块
   - 界面渲染模块 → 应用新样式到组件 → 重新渲染相关组件
   - 动态样式替换模块 → 记录样式变更历史 → 支持撤销操作
   - 用户保存样式配置 → 动态样式替换模块 → 保存到localStorage和服务器

7. **背景替换流程**：
   - 用户选择背景类型 → 动态样式替换模块 → 加载背景配置面板
   - 用户配置背景参数 → 动态样式替换模块 → 生成背景样式
   - 动态样式替换模块 → 应用背景样式到报表画布或组件
   - 界面渲染模块 → 更新背景显示 → 实时预览效果

8. **图片替换流程**：
   - 用户选择图片组件 → 动态样式替换模块 → 显示图片选择界面
   - 用户选择图片源（URL/上传/图片库） → 动态样式替换模块 → 验证图片有效性
   - 图片上传 → 文件存储系统 → 返回图片URL
   - 动态样式替换模块 → 更新组件图片属性 → 通知界面渲染模块
   - 界面渲染模块 → 更新图片组件显示

9. **主题应用流程**：
   - 用户选择主题 → 动态样式替换模块 → 加载主题配置
   - 动态样式替换模块 → 批量应用主题样式到报表和组件
   - 界面渲染模块 → 更新所有组件样式 → 应用主题效果
   - 动态样式替换模块 → 保存主题配置

### 6.2 设计态与运行态交互
**Schema传递**：
- 设计态生成schema文件 → 存储到文件系统或对象存储
- 运行态读取schema文件 → 解析并渲染
- Schema版本管理 → 支持多版本并存

**数据源配置**：
- 设计态配置数据源连接信息 → 保存到schema
- 运行态读取数据源配置 → 建立连接 → 执行查询

**交互配置**：
- 设计态配置交互规则 → 保存到schema
- 运行态解析交互配置 → 绑定事件监听 → 执行交互逻辑
- 设计态配置动态事件（REST API接口、参数映射、响应处理等） → 保存到schema的interactions字段
- 运行态解析动态事件配置 → 在交互事件触发时发送REST API请求 → 处理响应并执行后续动作

**国际化配置**：
- 设计态生成资源ID（KeyID）并保存到资源库 → Schema中存储资源ID而非直接存储文本
- 设计态支持导出资源ID及其对应的中文描述 → 提供给翻译人员翻译
- 设计态支持导入翻译后的资源ID与多语言文本映射 → 更新资源库
- 运行态根据用户语言偏好 → 从schema中读取资源ID → 从资源库查询对应语言的文本 → 渲染界面
- 系统界面文本 → 从文本资源模块加载 → 根据用户语言偏好显示

**样式配置**：
- 设计态配置报表和组件的默认样式 → 保存到schema的style字段
- 运行态读取schema的默认样式 → 应用默认样式到报表和组件
- 运行态支持动态修改样式 → 样式配置保存在用户配置或报表配置中
- 运行态样式配置优先级：用户自定义样式 > 用户配置样式 > schema默认样式
- 样式配置支持保存和加载 → 用户可保存样式配置，下次加载时自动应用

- resource_value：资源值（翻译文本）
- module：所属模块（common/design/runtime）
- create_time：创建时间
- update_time：更新时间

#### 9.1.6 资源库表（resource_library）
- resource_id：资源ID（主键，KeyID）

## 10. 接口设计

### 10.1 报表访问接口
- `GET /api/runtime/reports`：获取可访问报表列表
- `GET /api/runtime/reports/{id}`：获取报表Schema
- `GET /api/runtime/reports/{id}/data`：获取报表数据

### 10.2 数据查询接口
- `POST /api/runtime/query`：执行数据查询
- `GET /api/runtime/query/{id}/status`：查询执行状态
- `GET /api/runtime/query/{id}/result`：获取查询结果

### 10.3 交互接口
- `POST /api/runtime/interaction`：执行交互操作
  - 请求体：`{ "componentId": "string", "eventType": "string", "params": {} }`
  - 支持交互类型：下钻、关联、跳转、过滤、弹窗、刷新、动态事件
- `GET /api/runtime/interaction/{id}/result`：获取交互结果
- `POST /api/runtime/interaction/dynamic-event`：执行动态事件，发送REST API请求
  - 请求体：`{ "apiConfig": {...}, "authConfig": {...}, "paramMapping": {...}, "params": {...} }`
  - 响应：`{ "success": true, "data": {...}, "statusCode": 200 }`

### 10.4 运行态国际化接口（基于资源ID）
- `GET /api/runtime/i18n/user-preference`：获取当前用户语言偏好
- `PUT /api/runtime/i18n/user-preference`：设置当前用户语言偏好
- `GET /api/runtime/i18n/resources/{resourceId}/text`：根据资源ID获取指定语言的文本
  - 查询参数：`languageCode=zh-CN|en-US`（必填）
  - 响应：`{ "resourceId": "RID-20240101-001", "text": "销售数据" }`
- `POST /api/runtime/i18n/resources/batch-texts`：批量获取多个资源ID的文本
  - 请求体：`{ "resourceIds": ["RID-20240101-001", "RID-20240101-002"], "languageCode": "zh-CN" }`
  - 响应：`{ "texts": { "RID-20240101-001": "销售数据", "RID-20240101-002": "月份" } }`
- `GET /api/runtime/i18n/reports/{reportId}/localized-content`：获取报表的本地化内容（基于资源ID）
  - 查询参数：`languageCode=zh-CN|en-US`（必填）
  - 响应：包含资源ID到文本的映射表
- `GET /api/runtime/i18n/components/{componentId}/localized-text`：获取组件的本地化文本（基于资源ID）
  - 查询参数：`languageCode=zh-CN|en-US`（必填）
- `GET /api/runtime/i18n/system-text/{languageCode}`：获取系统界面文本资源
- `POST /api/runtime/i18n/switch-language`：切换语言并获取更新后的资源

### 10.5 动态样式替换接口
- `PUT /api/runtime/style/reports/{reportId}/background`：替换报表背景
- `PUT /api/runtime/style/components/{componentId}/background`：替换组件背景
- `PUT /api/runtime/style/components/{componentId}/image`：替换图片组件的图片
- `PUT /api/runtime/style/components/{componentId}`：替换组件样式
- `PUT /api/runtime/style/components/batch`：批量替换组件样式
- `POST /api/runtime/style/reports/{reportId}/theme`：应用预设主题
- `POST /api/runtime/style/reports/{reportId}/config`：保存样式配置
- `GET /api/runtime/style/reports/{reportId}/config`：加载样式配置
- `DELETE /api/runtime/style/reports/{reportId}/reset`：重置样式到默认值
- `POST /api/runtime/style/components/{componentId}/preview`：预览样式变更
- `POST /api/runtime/style/reports/{reportId}/rollback`：回滚样式变更
- `POST /api/runtime/style/images/upload`：上传图片文件
- `GET /api/runtime/style/themes`：获取预设主题列表

## 11. 异常处理

### 11.1 运行态异常
- **Schema解析失败**：记录错误日志，返回友好错误页面
- **数据查询失败**：返回错误信息，支持重试
- **权限验证失败**：返回403错误，提示权限不足
- **交互执行失败**：记录错误日志，不影响其他功能
- **动态事件执行失败**：
  - API请求失败：根据配置的重试策略执行重试，重试失败后执行降级策略（显示错误、使用默认值、忽略等）
  - API请求超时：提示请求超时，支持配置重试机制
  - API响应解析失败：提示响应格式错误，使用默认处理策略
  - 认证失败：提示认证错误，记录错误日志
- **运行态国际化异常**：
  - 用户语言偏好获取失败：使用系统默认语言（zh-CN），记录错误日志
  - 报表本地化内容加载失败：使用schema中的原始文本，不影响报表显示
  - 语言资源文件加载失败：使用默认语言资源，记录错误并提示用户
  - 语言切换失败：保持当前语言设置，提示用户稍后重试，记录错误日志
  - 组件本地化文本缺失：使用默认语言（zh-CN）文本，如仍缺失则使用原始文本或资源键
- **动态样式替换异常**：
  - 样式配置加载失败：使用schema中的默认样式，记录错误日志
  - 图片上传失败：提示上传错误，允许重试，记录错误日志
  - 图片URL无效：提示URL无效，使用占位图，记录错误日志
  - 样式应用失败：保持当前样式，提示用户稍后重试，记录错误日志
  - 样式配置保存失败：提示保存失败，样式配置保存在localStorage，记录错误日志
  - 主题应用失败：保持当前主题，提示用户稍后重试，记录错误日志
  - 样式回滚失败：保持当前样式，提示回滚失败，记录错误日志
  - 样式权限验证失败：拒绝样式修改操作，返回403错误，提示权限不足
