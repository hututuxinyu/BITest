# 报表发布功能实现说明

## 功能概述
实现了报表发布功能，允许用户将报表状态从`draft`（草稿）改为`published`（已发布），发布后的报表在运行态可见。

## 实现时间
2025-11-29

## 后端实现

### 1. ReportService.java
**新增方法**: `publishReport(String userId, String projectId, String reportId)`

**功能说明**:
- 验证工程是否存在且属于当前用户
- 验证报表是否存在
- 验证Schema文件是否存在且格式有效
- 将报表状态从`draft`更新为`published`
- 更新报表的更新时间

**关键逻辑**:
```java
// 验证Schema是否存在且有效
if (StringUtils.hasText(report.getSchemaFile())) {
    String schemaJson = schemaService.readSchema(reportId);
    SchemaValidator.SchemaValidationResult validationResult = schemaService.validateSchema(schemaJson);
    if (!validationResult.isValid()) {
        throw new RuntimeException("Schema验证失败，无法发布: " + validationResult.getErrorMessage());
    }
} else {
    throw new RuntimeException("报表Schema文件不存在，无法发布");
}

// 更新报表状态为published
report.setStatus("published");
report.setUpdateTime(LocalDateTime.now());
```

### 2. ReportController.java
**新增接口**: `POST /api/reports/project/{projectId}/{reportId}/publish`

**请求参数**:
- `userId` (Query参数): 用户ID
- `projectId` (Path参数): 工程ID
- `reportId` (Path参数): 报表ID

**响应**:
```json
{
  "success": true,
  "message": "发布报表成功",
  "data": {
    "reportId": "report-001",
    "reportName": "报表名称",
    "status": "published",
    ...
  }
}
```

### 3. 创建报表时的默认状态
在`ReportService.createReport()`方法中，新增报表的默认状态设置为`draft`：
```java
report.setStatus("draft"); // 默认状态为草稿
report.setCreatorId(userId);
```

## 前端实现

### 1. api.ts
**新增方法**: `publishReport(userId: string, projectId: string, reportId: string)`

**功能说明**:
- 调用后端发布接口
- 返回发布结果

**使用示例**:
```typescript
const response = await reportApi.publishReport(userId, projectId, reportId);
```

### 2. CanvasEditor.tsx
**新增处理函数**: `handlePublish()`

**功能说明**:
- 验证报表和工程是否存在
- 发布前先验证Schema有效性
- 显示确认对话框
- 调用发布API
- 发布成功后更新报表上下文状态
- 显示成功/失败提示

**发布按钮**:
- 位置：顶部导航栏右侧操作按钮组
- 图标：SendOutlined（旋转315度）
- 状态：
  - 已发布状态：按钮为`default`类型，禁用状态
  - 草稿状态：按钮为`dashed`类型，可用状态
- 提示：鼠标悬停显示"发布报表"或"已发布"

**发布流程**:
1. 用户点击发布按钮
2. 系统验证报表和工程是否存在
3. 系统验证Schema有效性
4. 如果Schema无效，显示警告对话框
5. 如果Schema有效，显示确认对话框
6. 用户确认后，调用发布API
7. 发布成功后，更新报表状态为`published`
8. 显示成功提示

## 安全验证

### 权限验证
- 验证工程是否属于当前用户
- 验证报表是否属于指定工程
- 确保用户只能发布自己的报表

### Schema验证
- 发布前必须验证Schema文件存在
- 发布前必须验证Schema格式有效
- Schema无效时不允许发布

## 错误处理

### 后端错误
- 工程不存在：返回"工程不存在"
- 无权访问：返回"无权访问该工程"
- 报表不存在：返回"报表不存在"
- 报表已发布：返回"报表已经是已发布状态，无需重复发布"
- Schema不存在：返回"报表Schema文件不存在，无法发布"
- Schema无效：返回"Schema验证失败，无法发布: [错误信息]"

### 前端错误
- 报表或工程不存在：显示警告提示
- Schema验证失败：显示警告对话框，显示具体错误信息
- 发布失败：显示错误提示

## 状态管理

### 报表状态
- `draft`: 草稿状态（默认）
- `published`: 已发布状态

### 状态转换
- 创建报表：默认状态为`draft`
- 发布报表：从`draft`转换为`published`
- 已发布的报表不能再次发布：
  - **前端**：发布按钮禁用，用户无法通过UI再次发布
  - **后端**：检查报表状态，如果已经是`published`状态，则抛出异常，防止重复发布

## 界面展示

### 状态标签
在报表编辑界面顶部显示报表状态标签：
- 草稿状态：金色标签，显示"草稿"
- 已发布状态：绿色标签，显示"已发布"

### 发布按钮
- 草稿状态：可用，虚线样式
- 已发布状态：禁用，默认样式
